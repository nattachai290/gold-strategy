History: attempt 1 died on HTTP 429 (`results/R000_FAILED.md`); attempt 2
cached 130/281 months on the runner's machine before its 3-rerun budget ran
out (`results/R000/FAILED_attempt2.md`). The feed throttles in windows of tens
of minutes (503, timeouts, resets). Changed since: 12 tries per file with
waits up to 15 min, 3 s between requests, a `status` command to measure
progress, and a progress-based stop rule instead of a fixed rerun count.

Paste everything below the line into the runner session opened on this repo.

## Steps

1. `git pull` on `main` (must contain this attempt-3 prompt). In every shell:
   `$env:PYTHONUTF8 = "1"`.
2. `pip install -e '.[dev]'`, then `pytest` (expect 30 passed).
3. `python -m goldml.dukascopy status` — record the line (expect `cached 130/281`).
4. Fetch loop. Launch each fetch **detached** so harness shell teardown cannot
   kill it, logging to a file outside the repo, e.g.
   `Start-Process -WindowStyle Hidden -FilePath python -ArgumentList "-m goldml.dukascopy fetch --start 2003-05 --end 2026-09" -RedirectStandardOutput $env:TEMP\r000_out.txt -RedirectStandardError $env:TEMP\r000_err.txt -PassThru`
   and wait for the process to exit. After each run:
   - run `python -m goldml.dukascopy status` and note cached months;
   - if it printed a manifest (stdout has `"manifest"`-style JSON with
     `"files"`), the fetch is complete: go to step 5;
   - otherwise wait 20 minutes and start the same command again.

   **Stop rule:** keep going as long as runs make progress. Stop and follow the
   failure rule only if **two consecutive runs add 0 new months**, or after
   **3 calendar days** from the start of this attempt.
   Failure rule: write the status lines, the run table (start, duration, exit,
   new months) and the last traceback to `results/R000/FAILED_attempt3.md`,
   commit and push that file only.
5. `python -m goldml.dukascopy restore` must print `restore OK` (it reuses the
   local cache, so it is quick). If it prints `HASH MISMATCH`, record it in the
   notes and continue.
6. Data-quality report (counts, gaps, spreads; no returns):
   `python -m goldml.dukascopy report | Out-File -Encoding utf8 results/R000/data_report.txt`
7. Write `results/R000/RUNNER_NOTES.md`: dates, OS, Python, `git rev-parse HEAD`,
   a table of every fetch run (start, duration, exit code, months cached after),
   the error mix if you have it (503 / timeouts / resets), the printed manifest,
   and any months reported as "no data". Facts only.
8. Commit and push. **Data files are not committed**: `git status` must show no
   `h1.csv.gz`, `fred.csv` or `raw/` files:
   ```bash
   git add data/snapshot_xau/manifest.json results/R000
   git commit -m "R000: Dukascopy XAUUSD H1 snapshot manifest + data report"
   git push origin main
   ```
9. Reply with the manifest and `results/R000/data_report.txt`.
