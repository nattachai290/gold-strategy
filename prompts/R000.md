# R000 — fetch XAUUSD hourly data from Dukascopy (runner prompt)

Paste everything below the line into the runner session opened on this repo.

---

You are the **runner** for this research repo. Read `CLAUDE.md` first. This
run only downloads data. It evaluates nothing.

## Rules

- Do not edit anything under `goldml/`, `tests/`, `experiments/`,
  `candidates/`, `docs/` or `data/snapshot/`.
- Do not run `python -m goldml.run`. Do not compute returns, Sharpe or any
  model output on this data. Do not print rows dated 2024-01-01 or later
  beyond what the fetch command prints itself.
- If a step fails, write the command and the full error to
  `results/R000_FAILED.md`, commit and push that file only, and stop.

## Steps

1. Use an up-to-date `main` that contains `goldml/dukascopy.py` and `prompts/R000.md`.
2. `pip install -e '.[dev]'`, then `pytest` (expect 21 passed).
3. Check access: `curl -sS -o /dev/null -w "%{http_code}\n" https://datafeed.dukascopy.com/datafeed/XAUUSD/2020/00/BID_candles_hour_1.bi5`
   must print `200`. If not, follow the failure rule.
4. Fetch (about 560 small files, roughly 5-15 minutes):
   ```bash
   python -m goldml.dukascopy fetch --start 2003-05 --end 2026-09
   ```
   It writes `data/snapshot_xau/{h1.csv.gz,fred.csv,manifest.json}` and prints
   the manifest. Exit code 1 means the manifest lists data issues: still commit
   the snapshot (the planner reviews it), do not try to fix anything.
5. Write `results/R000/RUNNER_NOTES.md`: date/time, `git rev-parse HEAD`,
   duration, the exit code, the printed manifest, and any months reported as
   "no data". Facts only.
6. Commit and push:
   ```bash
   git add data/snapshot_xau results/R000
   git commit -m "R000: Dukascopy XAUUSD H1 snapshot"
   git push origin main
   ```
7. Reply with the manifest.
